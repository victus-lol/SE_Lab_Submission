# Requirements Table - Corporate Mental Wellness Platform
**SRN:** PES2UG24CS016 | **Problem Statement 14** | **Date:** Aug 2026

> All requirements follow "The system shall..." format. FR-001 and NFR-001 are taken from the given problem statement (as instructed).

| Req ID | Type | Description | Priority | Acceptance Criteria | Rationale | Peer Comments |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **FR-001** | Functional | The system shall generate an anonymized pseudo-ID (like EMP-XXXX) for each employee so that they can book counseling sessions without showing their corporate email or employee ID to the therapist. | High | **Pass:** Therapist side only shows pseudo-ID, no real email/name is visible in booking data. **Fail:** Any PII (email, name, ID) appears in therapist dashboard or API data. | To keep employee identity private so people feel safe to seek help without fear at work. | Reviewed - looks good. Make sure pseudo-ID stays same for follow-up sessions. |
| **FR-002** | Functional | The system shall provide a self-assessment module using standard GAD-7 and PHQ-9 questionnaires to check stress, anxiety and depression levels. | High | **Pass:** Score (0-21) is calculated correctly within 1 sec after submitting and shows risk level. **Fail:** Score not calculated or data saved with real identity. | Helps employees identify early signs of burnout using validated clinical tools. | Good. Maybe add auto suggestion to book session if score is high. |
| **FR-003** | Functional | The system shall allow employees to search, filter and book confidential tele-counseling sessions with licensed therapists based on specialization, language and available slots. | High | **Pass:** Slot gets reserved without double booking and confirmation is sent within 2 sec without showing email. **Fail:** Double booking happens or email is exposed. | This is the main booking feature connecting employees to the right therapist. | Remember to handle timezone while showing slots - linked to NFR-001. |
| **FR-004** | Functional | The system shall provide a personal wellness dashboard where employees can log daily mood, sleep hours and see their stress trends over time. | Medium | **Pass:** Dashboard shows graphs for 7/30/90 days and data is only visible to the employee. **Fail:** Data not shown or visible to HR/admin. | Allows employees to track their own mental health progress privately. | Clarify - HR should only see overall anonymized stats (like >50 people aggregate). |
| **FR-005** | Functional | The system shall allow therapists to write and save anonymized session notes linked only to the pseudo-ID. | High | **Pass:** Notes are saved with pseudo-ID only, encrypted, and only treating therapist can view. **Fail:** Notes not saved or linked to real employee ID. | Needed for continuity of care while still keeping identity hidden. | Important for privacy compliance. |
| **NFR-001** | Non-Functional (Performance) | The appointment scheduler shall handle timezone conversions correctly for global offices and respond quickly even during peak load. | High | **Pass:** With 1000 concurrent bookings, timezone conversion is correct and response time P95 < 1 sec. **Fail:** Wrong time shown or response > 2 sec. | Needed for MNCs with offices in different timezones to avoid missed sessions. | Add test for daylight saving changes as well. |
| **NFR-002** | Non-Functional (Security) | The system shall encrypt all stored data (assessments, notes, wellness logs) with AES-256 and use TLS 1.3 for data in transit, with no plain PII stored. | High | **Pass:** Security scan shows no plain text PII in DB and TLS 1.3 on all APIs. **Fail:** Plain text data found or non-TLS connection allowed. | Required to meet HIPAA/GDPR and prevent employer from accessing private data. | Very important for security - must do. |

**Notes:**
- Total 5 FRs (FR-001 to FR-005) and 2 NFRs as required.
- Priorities decided based on core functionality vs additional features.
- All acceptance criteria are testable (pass/fail).
